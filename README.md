# SPA Backend Test Task

Тестовое задание на Backend-разработчика.

Нужно было сделать REST API для складского учёта SPA-оператора: хранить движения товаров, считать остатки, списывать товары по FEFO, рассчитывать потребность в закупке и показывать предупреждения по складу.

Проект написан на Python 3.11 с FastAPI, PostgreSQL и SQLAlchemy.

## Как запустить

Для запуска нужен Docker.

```bash
docker compose up --build
```

После запуска Swagger будет доступен по адресу:

```text
http://localhost:8000/docs
```

Проверка состояния API:

```text
http://localhost:8000/health
```

При первом запуске автоматически применяются миграции Alembic и загружаются стартовые данные.

## Как запустить тесты

Если контейнеры уже запущены:

```bash
docker compose exec api pytest -q
```

Либо можно запустить отдельный контейнер для тестов:

```bash
docker compose run --rm api pytest -q
```

## Основные таблицы

В базе используются таблицы:

- `products` — товары и параметры закупки;
- `locations` — SPA-объекты;
- `batches` — партии товара;
- `movements` — движения товара;
- `movement_allocations` — показывает, из каких партий был сделан расход;
- `open_orders` — открытые заказы и поставки в пути.

Отдельное поле с текущим остатком не хранится. Остаток считается по движениям:

```text
stock = receipt + return - consume - writeoff + correction
```

## FEFO

Для расхода используется FEFO — сначала списывается партия с ближайшим сроком годности.

Если в одной партии товара недостаточно, расход распределяется между несколькими партиями.

Просроченные партии для обычного расхода не используются. Для них есть операция `writeoff`.

## API

### POST `/api/movements`

Добавляет новое движение товара.

Пример прихода:

```json
{
  "date": "2026-09-24",
  "sku": "OIL-001",
  "location": "MS-01",
  "operation": "receipt",
  "qty": 10,
  "batch": "B-OIL-001-NEW",
  "doc_no": "INV-NEW-001"
}
```

Пример расхода:

```json
{
  "date": "2026-09-24",
  "sku": "OIL-001",
  "location": "MS-01",
  "operation": "consume",
  "qty": 4.5,
  "batch": null,
  "doc_no": "USE-NEW-001"
}
```

Доступные типы операций:

- `receipt`
- `consume`
- `writeoff`
- `return`
- `correction`

Основные проверки:

- неизвестный SKU — `404`;
- неизвестный объект — `404`;
- количество `<= 0` для `receipt` и `consume` — `422`;
- расход больше остатка — `422`;
- дата операции в будущем — `422`;
- повторный `doc_no` — `409`.

### GET `/api/movements`

Возвращает список движений.

Есть фильтры:

- `sku`
- `location`
- `operation`
- `date_from`
- `date_to`
- `limit`
- `offset`

В ответе возвращаются `items`, `total`, `limit` и `offset`.

### GET `/api/stock`

Показывает текущий складской остаток.

Для каждой позиции возвращается:

- текущий остаток;
- средний расход за день за последние 90 дней;
- запас в днях;
- ближайший срок годности.

Можно фильтровать по SKU и объекту.

### GET `/api/stock/{sku}`

Показывает подробную информацию по одному товару:

- остаток по объектам;
- партии;
- количество в каждой партии;
- сроки годности;
- цену поступления;
- номер накладной.

### POST `/api/forecast`

Считает рекомендуемый объём закупки.

Пример запроса:

```json
{
  "sku": "OIL-001",
  "location": "MS-01",
  "horizon_months": 3,
  "safety_stock_days": 14
}
```

Основные формулы:

```text
avg_daily_consumption = consumption_last_90_days / 90
forecast_demand = avg_daily_consumption * period_days
safety_stock = avg_daily_consumption * safety_stock_days
reorder_point = avg_daily_consumption * lead_time_days + safety_stock
raw_purchase = forecast_demand + safety_stock - current_stock - incoming_qty
```

Если закупка нужна, количество округляется вверх до размера упаковки и минимальной партии поставщика.

```text
recommended_purchase_qty = ceil(max(raw_purchase, min_order_qty) / pack_size) * pack_size
estimated_cost = recommended_purchase_qty * unit_price
```

В ответе также есть:

- текущий остаток;
- поставки в пути;
- точка заказа;
- ориентировочная стоимость;
- дата рекомендуемого заказа;
- дата возможного окончания запаса;
- блок `explanation` с формулами и исходными данными.

Для цены используется цена последнего прихода. Если её нет, используется цена из справочника товара.

### GET `/api/alerts`

Возвращает предупреждения по складу.

Сделаны три типа, которые требовались в задании:

- `deficit_risk` — запаса меньше, чем срок поставки;
- `expiry_risk` — у партии скоро заканчивается срок годности;
- `no_movement` — по товару давно не было движения.

Для предупреждений возвращается уровень важности и показатели, по которым оно было сформировано.

## Переменные окружения

Пример настроек находится в `.env.example`:

```env
POSTGRES_DB=spa
POSTGRES_USER=spa
POSTGRES_PASSWORD=spa
DATABASE_URL=postgresql+psycopg://spa:spa@db:5432/spa
EXPIRY_ALERT_DAYS=30
NO_MOVEMENT_DAYS=90
```

Для обычного запуска создавать `.env` не обязательно: в `docker-compose.yml` есть значения по умолчанию. Если нужно изменить настройки, можно скопировать пример:

```bash
cp .env.example .env
```

`POSTGRES_DB`, `POSTGRES_USER` и `POSTGRES_PASSWORD` задают настройки PostgreSQL. Если их менять, нужно также изменить `DATABASE_URL`.

`EXPIRY_ALERT_DAYS` задаёт, за сколько дней считать срок годности близким к окончанию.

`NO_MOVEMENT_DAYS` задаёт период, после которого позиция считается товаром без движения.

## Стартовые данные

В `app/seed.py` создаются тестовые данные, чтобы API можно было проверить сразу после запуска.

Добавляются два объекта:

- `MS-01` — Красная Поляна;
- `MS-02` — Сочи.

Также добавляются товары, партии, движения и открытые заказы.

В данных есть несколько специальных сценариев для проверки:

- дефицит `SCRB-020`;
- партия `FACE-040` с близким сроком годности;
- `TEX-061` без движения;
- поставка в пути для `OIL-001`;
- задержанная поставка для `WRAP-030`.

Повторный запуск seed не должен создавать дубликаты.

## Тесты

Сейчас в проекте 8 тестов.

Проверяются:

- FEFO;
- списание из нескольких партий;
- запрет расхода из просроченной партии;
- отказ при расходе больше остатка;
- расчёт остатка;
- округление закупки;
- расчёт точки заказа;
- ситуация, когда закупка не требуется;
- расчёт горизонта в несколько месяцев.

Запуск:

```bash
docker compose exec api pytest -q
```

На момент сдачи результат:

```text
8 passed
```
